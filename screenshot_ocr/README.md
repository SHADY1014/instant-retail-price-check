# 即时零售截图价格核查

面向内部价格巡查的 macOS 本地桌面工具。它将即时零售结算截图批量识别为结构化记录，支持人工核对、城市确认、重复项核查和 Excel 巡查表导出，并可基于已导出的数据生成汇总报告与汇报话术。

项目采用 macOS Vision OCR，在本地完成截图识别和字段解析；仅当用户主动使用“联网识别城市”时，才会将店铺名称发送至地图服务，并保留本地审计记录。

核心 OCR 与字段解析默认离线运行；联网城市识别只有在用户主动授权后才会发送店铺名称。

## 环境要求

- macOS 13+（需要 Vision Framework）
- Python 3.9+
- 系统自带 `swift` 命令行工具（Xcode Command Line Tools）
- 依赖：`PyQt5`、`openpyxl`、`Pillow`

```bash
cd screenshot_ocr

```

## 使用方法

### 启动

```bash
cd screenshot_ocr
python3 main.py
# 或
./启动.sh
```

### 操作流程

1. **导入截图**：支持三种方式导入美团、淘宝和京东闪送/秒送结算截图：
   - 拖拽图片到虚线框
   - 点击「选择图片」按钮批量选择
   - 点击「上传压缩包」按钮选择 zip 文件，自动解压并提取其中的图片
2. **OCR 识别**：点击「开始 OCR 识别」，系统调用 macOS Vision API 逐张识别
   - 识别中可点「取消识别」；已完成的图片会保留，未完成和失败的图片会标记为可重试。
   - 点击「重试失败项」只重新处理失败图片，不重置其他已人工修正的行。
3. **核对修正**：结果区会显示总条数、待核对数、已通过数。待核对记录以浅黄色标记；可勾选「仅看待核对」，鼠标悬停查看缺失字段或 OCR 失败原因，再直接修改表格内容。
4. **导出 Excel**：点击「导出 Excel」。若仍有待核对记录，程序会显示问题摘要；可返回继续核对，或确认后继续导出。
5. **生成汇总表**：选择已导出的巡查表 xlsx，生成含分省/分地级市汇总 + 核查明细表的汇总报告
6. **生成 U8 门店价格检查表**：点击「U8门店检查表」，选择巡查表 xlsx；仅转换燕京 U8，输出 12 列总部检查表，并附转换日志/待确认清单

辅助功能已按用途收纳在「城市与核查」「导出与汇总」「数据管理」菜单中，避免与主流程争夺注意力。

### 联网识别城市

- 首次使用会说明：仅将店铺名称发送至地图服务；截图和表格内容不会上传。
- 每次查询均需选择城市范围，结果只会在该白名单范围内产生。
- 程序会先展示候选城市，确认后才填入表格。授权时间、请求范围、候选与最终确认均保存在本地学习库，便于后续追溯。
- 多城市批量分配默认不勾选店铺，需由用户明确选择后再写入城市。

### 导出说明

- 每次导出在 `output/` 下自动创建子文件夹 `巡查表_YYYYMMDD_HHMMSS/`
- 巡查表保存为 `价格巡查表_YYYYMMDD_HHMMSS.xlsx`
- 后续用该巡查表生成的汇总表也会放入**同一个子文件夹**
- **分公司（A 列）默认填"漓泉销售公司"**，可在表格中修改
- 模板从 `模板.xlsx` 读取，每次导出复制副本，不修改模板文件
- M 列公式 `=G-L`（理论成交价）、N 列公式 `=G+J+K-L`（去除平台优惠价）自动写入
- O 列自动插入截图（WPS DISPIMG 格式嵌入单元格）
- 原有模板格式（合并单元格、样式、边框、行高、列宽）完整保留

### 汇总表说明

汇总表包含 2 个工作表：

**Sheet 1「汇总表」**（上下两区块）：
- 一、分省价格合格率汇总表：省份 / 产品 / 规格 / 合格线 / 总数 / 合格数 / 不合格数 / 合格率 / 最低·最高·平均理论成交价
- 二、分地级市价格合格率汇总表：增加「地级市」列

**Sheet 2「核查明细表」**：
- 完整 16 列（A~P）巡查表格式，深蓝标题行 + 蓝色表头
- 不合格行整行标红（字体颜色 `FFFF0000`）
- O 列嵌入对应截图

#### 合格标准

合格判定基于 **M 列「产品理论成交价格」**（= 成交价 G − 打包配送费 L）：

| 产品 | 规格 | 合格线 |
|------|------|--------|
| 漓泉1998（广东） | 500ml*12瓶/12听 | ≥ 70 元；第二档 ≥ 65 元 |
| 漓泉1998（广西） | 500ml*12瓶/12听 | ≥ 60 元；第二档 ≥ 55 元 |
| 漓泉1998 | 500ml*9听 | ≥ 45 元 |
| 燕京U8 | 500ml*12瓶 | ≥ 60 元 |
| 燕京U8 | 500ml*12听 | ≥ 60 元 |

汇总表中的“合格率”按第一档合格线计算；“第二档合格率”按第二档线以上数量计算，低于第二档线的数量单独列示。混合广东、广西数据时，表头显示“各省标准”，每个省份行按本省阈值统计。

## OCR 识别字段

| 列 | 字段 | 说明 |
|----|------|------|
| A | 分公司 | 默认"燕京啤酒（桂林漓泉）股份有限公司"，可修改 |
| B | 所属主要区域 | 自动填入「XX市」 |
| C | 平台 | 自动识别「美团闪购」「淘宝闪购」或「京东闪送」 |
| D | 店铺名称 | 截图中收货地址下方店铺名 |
| E | 产品名称 | 商品标题 + 规格（自动标准化） |
| F | 产品原价 | 商品标价 |
| G | 产品成交单价 | 底部最终支付价格 |
| H | 商品优惠 | 商家活动金额 |
| I | 满减活动 | 满减活动金额 |
| J | 优惠券 | 平台下发优惠券金额 |
| K | 红包 | 平台下发红包金额 |
| L | 打包、配送费 | 打包费 + 配送费 |
| M | 产品理论成交价格 | 公式 `=G-L`（合格判定依据） |
| N | 去除平台优惠价格 | 公式 `=G+J+K-L` |
| O | 图片 | 截图（WPS DISPIMG 嵌入单元格） |
| P | 备注 | 手动填写 |

## 品牌识别与产品名称标准化

系统识别产品品牌并标注，所有记录统一写入单一巡查表：

| 品牌 | 关键词 |
|------|--------|
| 燕京 / 漓泉 / 乌苏 | 漓泉、燕京、乌苏 |
| 雪花 | 雪花、勇闯、SnowBeer |
| 青岛 | 青岛、Tsingtao |
| 百威 | 百威、Budweiser |

产品名称标准化规则（示例）：
- 漓泉：统一为「漓泉1998啤酒 500ml*12瓶」
- 燕京：仅 U8 型号 →「燕京U8 500ml*12瓶」
- 雪花：区分 superX / 老雪 / 勇闯 / 清爽，按度数细分
- 青岛：区分原浆 / 奥古特 / 2000 / 白啤 / 纯生 / 经典 / 清爽
- 百威：区分纯生 / 铝罐 / 普通，按度数细分

## 技术架构

### OCR 引擎（ocr_engine.py）
- 使用 macOS Vision Framework 的 `VNRecognizeTextRequest`
- 通过内嵌 Swift 脚本经 `subprocess` 调用系统 `swift` CLI 执行
- 识别级别：`.accurate`，语言：`["zh-Hans", "en", "zh-Hant"]`
- 返回归一化坐标（0~1），Y 轴自底向上

### 字段解析（field_parser.py）
- 基于 OCR 文本坐标的规则匹配（非 LLM）
- 价格提取处理 OCR 误读：`¥461~` → `4.61`，3 位数 + 波浪号 → 除以 10
- 店铺名识别：在"选择收货地址"下方搜索含超市/便利店/店等关键词的文本
- 缩略图标签提取：左侧区域（left < 0.12）的"12听装"等规格信息

### Excel 写入（excel_writer.py）
- 基于模板复制，保留所有格式（合并单元格、样式、边框、行高、列宽）
- WPS DISPIMG 格式嵌入图片：手动注入 `xl/cellimages.xml` + `.rels` 到 xlsx zip
- O 列公式 `=_xlfn.DISPIMG("ID_xxx",1)` 引用嵌入图片

### 汇总表生成（summary_generator.py）
- 读取巡查表全部 16 列数据 + WPS cellimages 图片
- M/N 列手动计算（源文件公式无缓存值时的兜底）
- 合格判定基于 M 列理论成交价，不合格行整行标红

### 城市识别（city_detector.py）
识别结果按证据保守决策：
1. **店名提取**：从店铺名中直接匹配城市名（如"广州水荫路店"→广州）
2. **百度地图搜索建议**：搜索完整店铺名，从 POI 结果提取城市（网络请求，可关闭）
3. **分店名关键词推断**：从分店名的道路/地标关键词推断城市

以上证据会综合评分并比较候选分差；弱或歧义结果不会自动填入，而是进入人工确认。

## 📚 知识库（店铺/城市智能匹配 + 人工反馈学习）

主界面「📚 知识库」按钮打开学习系统，实现「人工修正一次，系统以后尽可能记住」：

- **数据库**：`data/ocr_learning.db`（SQLite，独立于 OCR 引擎），包含店铺标准表/别名表/城市匹配表/人工修正记录/投喂批次/匹配历史，首次启动自动迁移旧 `shop_city.db`
- **匹配优先级**：L1 标准名精确 → L2 别名精确 → L3 标准化精确 → L4 历史人工修正 → L5 高相似候选（仅候选，不自动使用）→ L6 原规则推断 → L7 人工确认
- **自动学习**：批量设置城市时，人工确认结果自动写入学习库；下次识别同店直接命中
- **Excel 投喂**：知识库页「导入 Excel」投喂人工修正后的巡查表（幂等：同文件重复导入自动跳过；同店不同城市标记 CONFLICT 不覆盖，由「冲突」页人工裁决）
- **重新匹配**：对当前表格所有店铺重新执行学习库匹配（含店名规范化，如「广卅」自动纠正为「广州」）

测试：`OCR_LEARNING_DB=/tmp/test.db python3 tests/test_learning_db.py`（独立测试库，不影响真实数据）
